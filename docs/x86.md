# x86-64 decompilation

Ember supports x86-64 ELF, Mach-O, PE32+, minidumps, and raw memory regions.
The pipeline models SysV and Win64 independently, including integer and XMM
argument lanes, stack arguments, return lanes, and caller-saved registers.

Without a declared signature, scalar reads of incoming XMM lanes recover
floating-point parameters. SysV's independent integer and floating-point
banks do not reveal their original source order; inferred signatures list
the integer prefix followed by the floating-point prefix. Metadata and user
signatures retain their declared order. An untouched RAX on a reachable exit
is treated as evidence of a void function instead of printing `return rax`.

Signed comparisons reinterpret operands at the instruction's width before C
integer promotion, including 8/16/32-bit values with their sign bit set.
Mach-O Objective-C calls also recover explicitly stored stack arguments for
format strings and known nil-terminated object lists such as
`initWithObjectsAndKeys:`.

## Modern instruction encodings

The decoder understands legacy, two/three-byte VEX, and common four-byte EVEX
forms. XMM, YMM, ZMM, and AVX-512 mask registers keep their encoded widths in
IR. Common map-`0F` AVX/AVX2 operations, map-`0F38` BMI/BMI2 and FMA3 forms,
mask/zero metadata, and `vzeroupper` are lifted. Rare map-`0F3A`,
gather/scatter, complete tuple broadcast, and compressed-displacement rules
remain explicit boundaries.

## Function discovery

Final enumeration rejects heuristic starts that land inside an already decoded
instruction. It also removes heuristic `sub_*` entries covered by a sized
symbol. This matters when a short-jump displacement or the second instruction
in a prologue happens to resemble another prologue: keeping the false start
truncates the real function and produces a decode error at the preceding
instruction.

Use `--no-cache` when comparing discovery algorithms across Ember builds. The
function cache version is bumped whenever discovery semantics change.

```sh
ember --no-cache --functions ./target
ember -d -s main ./target
```

## Stack buffers and arrays

A gap between stack slots is only array evidence when the slot is not assigned
as a scalar. Bounded library writes provide stronger minimum extents:

- `memset`, `memcpy`, `memmove`, `strncpy`, `read`, and `recv` use their byte
  count;
- `fgets` uses its capacity;
- `fread` uses `size * count` when both are constant and bounded.

Inline x86 string operations contribute extents too: `rep stosb/stosd/stosq`
records the filled destination and `rep movsb/movsd/movsq` records both copied
objects. This recovers large stack-resident MSVC C++ objects that never pass
through `memset` or `memcpy`.

This turns `memset(&local, 0, 14)` into `uint8_t local[14]` while keeping an
adjacent loop counter scalar.

## Pointer-depth recovery

Imported call parameter types refine the exact SSA value reaching the call,
not only a direct live-in register. Load inference then propagates that type
back to the address. For example, a value loaded through the second argument
and passed to `strcmp` proves the loaded value is `char*` and the argument is
`char**`—the usual `argv` shape even after an `-O0` stack spill/reload.

## Embedded debug metadata

PE images import standard COFF symbol-table functions, long names,
section-relative addresses, and auxiliary function sizes. Ember also reads the
common DWARF v4/v5 `.debug_info`/`.debug_abbrev` forms embedded in ELF, Mach-O,
or PE files. Concrete subprogram DIEs contribute:

- low/high-PC function extents;
- source or linkage names;
- return types;
- parameter names, pointer/reference depth, and variadic markers;
- specification/abstract-origin type reuse.

User annotations remain authoritative, followed by embedded debug signatures
and PDB signatures. Unsupported DWARF forms are skipped rather than preventing
the binary from loading.

## Strings and imported prototypes

Generic immediate decoding requires at least two printable bytes and refuses
to interpret executable-section bytes as strings. A parameter proven to be
`char*` may accept a one-character NUL-terminated literal, which recovers modes
such as `fopen(path, "a")` without turning opcode bytes into fake text.

The built-in prototype set includes common POSIX/libc calls plus Win32/MSVCRT
startup and anti-debug routines. ISO C23/C99 `scanf` redirect names are treated
as their libc equivalents, and `%s`, `%c`, and scanset destinations decay stack
arrays correctly. Fixed prototypes trim stale ABI lanes before pseudo-C
emission; unknown internal calls remain conservative.

Win64 process tooling includes exact signatures for Toolhelp enumeration,
`OpenProcess`, `ReadProcessMemory`, `WriteProcessMemory`, `VirtualQueryEx`, and
window lookup. Pointer parameters also refine pointer-valued stack locals.

MSVC security-cookie epilogues are recognized before dead-code elimination.
The `saved_cookie ^ rsp` helper is suppressed while the value placed in RAX
before it remains the source-level return; byte-return Phis receive initialized
per-path values instead of leaking undefined `rax_N` names.
