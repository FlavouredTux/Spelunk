# x86-64 decompilation

Spelunk supports x86-64 ELF, Mach-O, PE32+, minidumps, and raw memory regions.
The pipeline models SysV and Win64 independently, including integer and XMM
argument lanes, stack arguments, return lanes, and caller-saved registers.

Without a declared signature, scalar reads of incoming XMM lanes recover
floating-point parameters. SysV's independent integer and floating-point
banks do not reveal their original source order; inferred signatures list
the integer prefix followed by the floating-point prefix. Metadata and user
signatures retain their declared order. An untouched RAX on a reachable exit
is treated as evidence of a void function instead of printing `return rax`.

Signed comparisons reinterpret operands at the instruction's width before C
integer promotion, including 8/16/32-bit values with their sign bit set.
Mach-O Objective-C calls also recover explicitly stored stack arguments for
format strings and known nil-terminated object lists such as
`initWithObjectsAndKeys:`.

Fixed call signatures select integer registers, scalar XMM registers, and
overflow stack slots through the same ABI layout. Callee analysis can also
recover scalar FP lanes without a signature, including arguments forwarded
without local arithmetic. A function-pointer initializer can supply signature
evidence while the emitted call still reads the pointer at runtime. A scalar
FP result used only as the return takes precedence over an integer scratch
value already consumed by the body; explicit signatures remain authoritative.

Variable shifts retain the CPU's implicit count mask (`& 63` for 64-bit
operands, `& 31` otherwise), even when there is no separate AND instruction.
The mask is omitted only when a bound on every loop back edge proves that a
synchronized shift counter stays within the operand width. Unbounded counts,
signed or bypassable guards, and potentially overflowing counters keep it.
Flag-preservation logic for a zero count does not become a conditional shift
in the value expression.

Supported Itanium free-function symbols supply parameter types even without
debug info. References become pointers in pseudo-C. Most non-template symbols
do not encode the return type; that still needs inference or an annotation.
C++ exception-runtime calls use fixed prototypes, and shared non-returning
throw tails retain their incoming values rather than duplicating the body.

For guarded loops with a common normal continuation, non-returning error paths
stay at their in-loop conditions. The normal continuation is emitted once after
the loop, rather than inside a conditional that other exits must jump into.

When the return register merely retains an argument used as the final output
address, its source return type may be `void` or a pointer. Without a declared
return type, pseudo-C marks this as `unknown_return_t` and comments the register
value at `return;`. This is an explicit uncertainty marker, not a C type or a
claim that the function returns void. A supplied signature overrides it. Strict
C export continues to model the physical ABI return register.

Scoped `-d` only decodes the selected function. It does not implicitly build
the whole-binary caller graph for an xref header; use `--refs-to` or `--xrefs`
when that global analysis is wanted. Interactive terminals receive loading and
analysis progress messages on stderr.

`--callees` combines reachable CFG edges with direct calls found elsewhere in
an authoritative function extent, including exception landing pads. JSON marks
those as `direct_extent`, reports whether the extent was complete, and lists
unresolved indirect call sites separately.

Mach-O relocatable objects use compiler-emitted compact-unwind records for
function extents. A named object function without symbol size or unwind extent
is rejected instead of receiving an inferred discovery window. `--disasm-at`
also warns when a requested address is provably in the middle of an instruction.
Its `--count` option limits only the displayed instruction list; trampoline
length, relocation hazards, and first-basic-block end are computed independently
and therefore have identical semantics in plain and JSON output.

Unresolved x64 virtual calls can omit an unchanged trailing copy of the
receiver when no predecessor writes that argument register. Such argument
lists are marked inferred; explicit register preparation and declared
signatures take precedence. This is a presentation heuristic, not proof of
the original prototype, and strict C export retains the conservative call.

Entry `push rax` stack reservations are hidden when the saved bytes are not
read before replacement. Partially used reservations retain the actual local
access widths instead of creating a fictitious eight-byte initialization.
Strict C export requires the entire escaped reservation to be initialized;
it does not assume an unknown callee stays within an inferred subobject.
For a direct local callee whose bounded instructions only write through the
pointer, an unused entry `push rax` can be omitted. A byte written on every
returning path is then treated as initialized. A callee that reads the
reservation or passes the pointer to unknown code still keeps the export
incomplete.

Mach-O function-start tables are read for images whose `__TEXT` base is zero,
including dylibs. Symbol-table and export-trie records for the same name and
address are coalesced after their extents are recovered.

## C exports

`--emit-c` runs the pseudo-C pipeline and includes standard headers, required
helper definitions, and external function/global declarations. Scalar memory
accesses use small `memcpy` helpers, preserving byte offsets and unaligned
accesses without inventing a record layout. Integer add/subtract/multiply
expressions retain their machine-width wraparound. Invalid linker identifiers
on globals receive stable C names with their addresses appended.

```sh
spelunk --emit-c -s function_name --annotations context.anns target.dylib > function.c
python scripts/check_pseudocode.py function.c
clang -c function.c
```

Every name the export mentions is declared ahead of the function. Record types
recovered from debug info arrive as a name with no layout: one used only
through a pointer is forward-declared as an opaque `struct`, which keeps the
recovered name without inventing fields. Flag predicates, conversions, rotates
and REP MOVS / STOS are defined inline from their machine meaning. When the
analysis reports unresolved operations, types, or register reads, `--emit-c`
fails without printing partial C. This includes unmodeled x87 instructions
that remain visible as comments in the `-p` view. Undecoded control-flow
targets also reject the export.

Literal printf formats supply argument casts for pointer and numeric
conversions, including positional arguments and width/precision arguments.
The `vprintf` family retains its single `va_list` argument instead of treating
it as the first value named by the format string.

Declarations make compilation possible; linking still requires implementations
of external functions and storage for external globals. Supply known SDK
signatures and record types through annotations or `--headers` when available.
Inferred prototypes describe available ABI evidence, not recovered source-level
contracts. Unsupported memory widths produce an explicit compile-time error;
other unsupported operations remain visible to the output checker.

Scalar floating-point joins and constant arguments used only by calls are
copied on incoming CFG edges. The shared values live at function scope, so
the output does not reuse a branch-local temporary or reevaluate a condition
that may dereference a null pointer. Tail wrappers preserve the argument and
FP-return metadata of standard conversions such as `atof`.

## Executable checks and real-binary audits

`x64_fp_edge_semantics` compares scalar floating-point arithmetic, flag
consumers, and conversions with native x86 execution and exported C at `-O0`
and `-O2`. Arithmetic cases include self-subtraction, self-division, and zero
operands, checking NaNs, infinities, and the sign of zero. Integer-to-float
cases check signed 32/64-bit interpretation for register and memory sources,
including unsigned annotations and unrelated upper register bits. Integer
folding rules do not rewrite floating arithmetic or interpret IEEE immediate
bits as integer constants. All 16 condition codes run through SETcc, CMOVcc,
and branches after
COMISS/COMISD and UCOMISS/UCOMISD, including NaNs and signed zero. A register
overwrite after the comparison checks that parity still describes the original
operands. Conversion checks cover float/double sources, register/memory forms,
32/64-bit destinations, 32-bit zero extension, and values around both signed
limits. A UBSan/float-cast-overflow run checks truncating conversions under all four
rounding modes. Invalid conversions return the destination-width integer
indefinite value without an out-of-range C cast. These checks model results
with floating-point exceptions masked; they do not reproduce MXCSR exception
status or unmasked traps.

`macho_pipeline_semantics` builds a small Intel Mach-O with Clang and
`ld64.lld`. It compares original instructions executed by Unicorn, native C,
and emitted C compiled at `-O0`/`-O2`, with and without stripped symbols.
Checks include float/double returns, mixed register banks, integer and floating
overflow stack arguments, ordered helper-argument traces, a mutable function pointer, and
every byte of a guarded memory buffer. Helper signatures supply the ABI
oracle for the stack cases; the register-only wrappers also run without
signatures. It requires Linux x86-64, Clang, `ld64.lld`, `llvm-strip`,
`llvm-nm`, and Python `unicorn`.
Literal checks preserve signed zero and the bit patterns of infinity and NaN.

```sh
ctest --test-dir build -R 'macho_pipeline_semantics|pseudocode_check_unit'
python scripts/macho_quality_check.py path/to/library.dylib \
    --spelunk ./build/cli/spelunk --output /tmp/macho-audit --sample 24
python scripts/check_pseudocode.py emitted.c --preamble known_types.h --json
```

The audit copies the Intel slice before stripping it, measures retained
entry addresses against defined text symbols, and samples the same addresses
in both copies using a fixed seed. Dynamic exports and runtime metadata can
remain after stripping. Reports retain the input hash, function inventories,
missing entries, generated output, and compiler diagnostics.

The output checker catches undeclared identifiers, incorrect call arity when
prototypes are supplied, invalid member accesses, and unreachable statements.
Unknown SDK types and deliberate pseudo-C extensions also cause diagnostics;
these are compilation gaps, not an equivalence score. The executable tests
check semantics separately.
It also rejects explicit unresolved-expression, unresolved-SSA, and
structurer-failure markers, even when their placeholder C would compile.

`elf_c_export_check` emits C for every ELF fixture in the tree and runs the
output checker over it - no execution, no hand-written preamble - so a
declaration gap on unfamiliar input fails a test rather than waiting to be
found by hand. Fixtures whose export is still incomplete are listed in the
test with the reason, and the list is checked in both directions: closing a
gap fails the test until its entry is removed.
Unexpected exporter errors and crashes fail the sweep, including on fixtures
with a documented gap; incomplete exports must not leak partial C to stdout.

`cmpss_export_semantics` checks all eight legacy `CMPSS` predicates against
native execution and emitted C at `-O0`/`-O2`. It compares complete 128-bit
results for register and memory sources, including NaNs, infinities, signed
zero, subnormals, and scalar arithmetic/moves before the comparison. Upper
lanes are preserved across scalar writes, while scalar memory loads clear
them. The `fp_scalar` fixture's main function also exports and executes in
the same test. These checks cover result bits and memory, not MXCSR
exception flags or unmasked floating-point traps. VEX/EVEX `VCMPSS` remains
unsupported and is rejected by the decoder.

`macho_c_export_semantics` compiles each selected export without an additional
preamble, then compares complete return bits, memory bytes, and helper effects
against original Mach-O instructions and native C. Its fixtures cover null and
empty-string branches, joined call results, mixed-width packed records, and
indirect dispatch. A separate UBSan executable checks the exported scalar
memory and arithmetic paths. Use `--emit-c` with `macho_quality_check.py` to
audit this export view instead of the default presentation.

## Modern instruction encodings

The decoder understands legacy, two/three-byte VEX, and common four-byte EVEX
forms. XMM, YMM, ZMM, and AVX-512 mask registers keep their encoded widths in
IR. Common map-`0F` AVX/AVX2 operations, map-`0F38` BMI/BMI2 and FMA3 forms,
mask/zero metadata, and `vzeroupper` are lifted. Rare map-`0F3A`,
gather/scatter, complete tuple broadcast, and compressed-displacement rules
remain explicit boundaries.

## Function discovery

Final enumeration rejects heuristic starts that land inside an already decoded
instruction. It also removes heuristic `sub_*` entries covered by a sized
symbol. This matters when a short-jump displacement or the second instruction
in a prologue happens to resemble another prologue: keeping the false start
truncates the real function and produces a decode error at the preceding
instruction.

Use `--no-cache` when comparing discovery algorithms across Spelunk builds. The
function cache version is bumped whenever discovery semantics change.

```sh
spelunk --no-cache --functions ./target
spelunk -d -s main ./target
```

## Stack buffers and arrays

A gap between stack slots is only array evidence when the slot is not assigned
as a scalar. Bounded library writes provide stronger minimum extents:

- `memset`, `memcpy`, `memmove`, `strncpy`, `read`, and `recv` use their byte
  count;
- `fgets` uses its capacity;
- `fread` uses `size * count` when both are constant and bounded.

Inline x86 string operations contribute extents too: `rep stosb/stosd/stosq`
records the filled destination and `rep movsb/movsd/movsq` records both copied
objects. This recovers large stack-resident MSVC C++ objects that never pass
through `memset` or `memcpy`.

This turns `memset(&local, 0, 14)` into `uint8_t local[14]` while keeping an
adjacent loop counter scalar.

## Pointer-depth recovery

Imported call parameter types refine the exact SSA value reaching the call,
not only a direct live-in register. Load inference then propagates that type
back to the address. For example, a value loaded through the second argument
and passed to `strcmp` proves the loaded value is `char*` and the argument is
`char**`—the usual `argv` shape even after an `-O0` stack spill/reload.

## Embedded debug metadata

PE images import standard COFF symbol-table functions, long names,
section-relative addresses, and auxiliary function sizes. Spelunk also reads the
common DWARF v4/v5 `.debug_info`/`.debug_abbrev` forms embedded in ELF, Mach-O,
or PE files. Concrete subprogram DIEs contribute:

- low/high-PC function extents;
- source or linkage names;
- return types;
- parameter names, pointer/reference depth, and variadic markers;
- specification/abstract-origin type reuse.

User annotations remain authoritative, followed by embedded debug signatures
and PDB signatures. Unsupported DWARF forms are skipped rather than preventing
the binary from loading.

## Strings and imported prototypes

Generic immediate decoding requires at least two printable bytes and refuses
to interpret executable-section bytes as strings. A parameter proven to be
`char*` may accept a one-character NUL-terminated literal, which recovers modes
such as `fopen(path, "a")` without turning opcode bytes into fake text.

The built-in prototype set includes common POSIX/libc calls plus Win32/MSVCRT
startup and anti-debug routines. ISO C23/C99 `scanf` redirect names are treated
as their libc equivalents, and `%s`, `%c`, and scanset destinations decay stack
arrays correctly. Fixed prototypes trim stale ABI lanes before pseudo-C
emission; unknown internal calls remain conservative.

Win64 process tooling includes exact signatures for Toolhelp enumeration,
`OpenProcess`, `ReadProcessMemory`, `WriteProcessMemory`, `VirtualQueryEx`, and
window lookup. Pointer parameters also refine pointer-valued stack locals.

MSVC security-cookie epilogues are recognized before dead-code elimination.
The `saved_cookie ^ rsp` helper is suppressed while the value placed in RAX
before it remains the source-level return; byte-return Phis receive initialized
per-path values instead of leaking undefined `rax_N` names.

## Recovered types and carry rotates

Embedded DWARF supplies callback typedefs and named struct fields when available,
including Clang's DWARF 5 indexed strings and addresses. Bit-fields and dynamic
member offsets are not imported. Explicit annotations take precedence.

C exports model rotate-through-carry values and the carry flag for 8-, 16-,
32- and 64-bit operands, including masked counts and zero-count behavior.
